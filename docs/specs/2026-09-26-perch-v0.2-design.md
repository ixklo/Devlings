# Perch v0.2: ChatGPT-style pet redesign

Date: 2026-09-26. Supersedes the UI parts of `2026-09-25-perch-design.md`. The Watch (hooks), Ask (`claude -p`) and money-guard behavior stay as they are.

## Goal

Make Perch look and behave like the Codex pets in the ChatGPT desktop app:
- A pixel-art animated pet floating above all windows.
- Thread status shown as speech-bubble cards above the pet.
- A small control bar under the pet.
- A compact composer and mini chat that open from the pet itself, not from a separate framed window.

Reference: ChatGPT "Pets" docs, and the Codex pet contract in openai/skills `hatch-pet` (Apache-2.0).

## 1. Pet sprite format (Codex-compatible)

- Atlas: PNG or WebP, **1536×1872**, **8 columns × 9 rows**, cell **192×208**, transparent. Unused cells are fully transparent.
- Rows, with used columns and frame durations in ms:

| Row | Name | Frames | Durations |
|---|---|---|---|
| 0 | idle | 6 | 280,110,110,140,140,320 |
| 1 | running-right | 8 | 120×7, then 220 |
| 2 | running-left | 8 | 120×7, then 220 |
| 3 | waving | 4 | 140,140,140,280 |
| 4 | jumping | 5 | 140,140,140,140,280 |
| 5 | failed | 8 | 140×7, then 240 |
| 6 | waiting | 6 | 150×5, then 260 |
| 7 | running (working, not locomotion) | 6 | 120×5, then 220 |
| 8 | review | 6 | 150×5, then 280 |

- Package: folder `<id>/` containing `pet.json` and the spritesheet. Manifest:
  `{"id","displayName","description","spritesheetPath"}`.
- Pet sources, merged in this order (later ids with the same name are ignored):
  1. **Bundled:** `src-tauri/pets/<id>/`, shipped as Tauri bundle resources `pets/**`. Bundled ids: `perch` (teal bird, default), `ember` (orange), `plum` (purple).
  2. **Perch user pets:** `<app data>/pets/<id>/`.
  3. **Codex pets:** `${CODEX_HOME:-~/.codex}/pets/<id>/`.
- Validation: the manifest must parse, and the sprite file must exist and be ≤ 20 MiB. Dimensions are not checked by the backend; the frontend renders assuming the contract.

## 2. Pet → animation mapping

Overall pet state, highest priority first (ChatGPT order):
**setup** > **needs_input** > **blocked** > **ready** > **running** > **idle**.

| Pet state | Row |
|---|---|
| idle | 0 idle |
| running | 7 running |
| needs_input | 6 waiting |
| blocked | 5 failed |
| ready | 8 review (after one play of 4 jumping when a thread first becomes ready) |
| setup | 6 waiting |

Interaction overrides, which return to the state row when done:
- Hover: row 3 waving, played once, at most once per 4 s.
- Drag: row 1 when the window moves right, row 2 when it moves left, until 150 ms with no movement.
- `prefers-reduced-motion`: static frame 0 of the state's row.

## 3. Thread model (backend)

A thread is one Claude Code session (`session_id`), from Watch or Ask.

```ts
type ThreadStatus = "running" | "needs_input" | "ready" | "blocked" | "idle";
type ThreadInfo = {
  sessionId: string; project: string; projectName: string;
  source: "watch" | "ask"; status: ThreadStatus;
  label: string | null;    // latest step, e.g. "Editing app.tsx"
  excerpt: string | null;  // latest final reply excerpt (≤ 200 chars) for ready/blocked
  updatedAt: number;       // epoch ms
  unread: boolean;         // ready/blocked not yet viewed
};
```

Kind → status: prompt/step/blocked/reply_delta → `running`; needs_you → `needs_input`; done → `ready` + unread; failed → `blocked` + unread; started → `idle`; ended → the thread is removed.

- `mark_viewed(sessionId)` sets `unread=false`. Ready or blocked threads that have been viewed become `idle`.
- **Visible threads** (in bubbles) are those that are not idle, plus running ones updated within 30 min. Sorted by priority (needs_input, blocked, ready, running), then newest.
- Threads are pruned 1 h after the last update, unless they are unread.
- The pet state is computed from visible threads plus setup (priority in §2).
- Notifications: an OS notification is shown when a thread becomes ready, needs_input or blocked, if notifications are on and that thread isn't the focused thread (`set_focused_thread`).

## 4. Windows

- **`pet`** (overlay): 380×600 logical, transparent, frameless, always on top, skip taskbar, not resizable, no shadow, not focused on start.
  - Layout, bottom to top: control bar, pet sprite (bottom-centered), then the bubble stack, composer or thread view above the pet.
  - **Click-through:** the frontend reports interactive rectangles; the backend polls the cursor every 33 ms and calls `set_ignore_cursor_events(!inside_any_rect)`, only when that value changes. Rectangles are window-relative CSS px, padded by 6 px.
  - Position: saved as the window's top-left. The default is the primary work area's bottom-right, minus the window size and a 16 px margin. It is clamped into a visible work area at startup.
  - Keyboard (when the pet window is focused): arrow keys move 20 px, Escape resets to the default position.
- **`settings`** (replaces `panel`): 480×680, decorated, hidden by default. Hosts onboarding (first run) and Settings. Closing it hides it.

## 5. Commands and events (contract between backend and frontend)

Events:
- `snapshot`: `Snapshot`, emitted on every change.
- `pet-event`: `PetEvent` (unchanged).
- `pet-open` (to the pet window): `{ view: "compose" } | { view: "thread", sessionId: string }`, from the tray or shortcut.
- `settings-view` (to the settings window): `"settings" | "onboarding"`.
- `pet-pointer` (to the pet window): `string | null`, the `id` of the hit rect under the cursor, emitted when it changes. The frontend uses it for the hover wave and control-bar visibility. The webview can't track hover itself: once the window turns click-through, it never sees the pointer leave.

```ts
type PetState = "idle" | "running" | "needs_input" | "ready" | "blocked" | "setup";
type Snapshot = {
  config: Config;              // + petId: string, petScale: number, threadsCollapsed: boolean
  petState: PetState;
  threads: ThreadInfo[];       // visible threads, already sorted
  projects: ProjectEntry[];
  running: string[];           // projects with an active Ask run
  setup: SetupStatus;          // unchanged
};
type PetInfo = { id: string; displayName: string; description: string; source: "bundled" | "perch" | "codex" };
type HitRect = { x: number; y: number; w: number; h: number; id?: string }; // id = data-hit value ("pet", "bar")
```

Commands (JS name, args, return):
- Existing, unchanged: `get_snapshot`, `recheck_setup`, `set_pet_name {name}`, `install_hooks`, `move_hooks_port`, `uninstall_hooks`, `decline_hooks`, `set_claude_path {path}`, `add_project {path}`, `set_permission_mode {project, mode}`, `new_conversation {project}`, `load_conversation {project}` → ChatTurn[], `ask {project, prompt}`, `stop_ask {project}`, `mark_credits_notice_seen`, `finish_onboarding`, `set_notifications {enabled}`, `set_launch_at_login {enabled}`, `save_pet_position {x, y}`.
- New:
  - `set_hit_regions {regions: HitRect[]}`
  - `list_pets` → PetInfo[]
  - `get_pet_sprite {id}` → string (data URL, `data:image/png;base64,…` or `image/webp`)
  - `set_pet {id}` → Snapshot
  - `set_pet_scale {scale}` → Snapshot (clamped 0.4–1.0; UI offers 0.45 / 0.6 / 0.8; default 0.6)
  - `mark_viewed {sessionId}` → Snapshot
  - `set_focused_thread {sessionId: string|null}`
  - `open_project {path}`: runs `code <path>` if VS Code's CLI is found, otherwise opens the folder in the file manager
  - `set_threads_collapsed {collapsed}` → Snapshot
  - `reset_pet_position`
  - `move_pet_by {dx, dy}` (logical px, saves the position; arrow keys)
  - `drag_pet_by {dx, dy}` (logical px, doesn't save; sent about once per frame while dragging)
  - `open_settings {view: "settings"|"onboarding"}`, `close_settings`
  - `open_pets_folder`: creates `<app data>/pets` if missing and opens it in the file manager
  - `show_pet_menu` (unchanged, now items: Settings, Change pet ▸ list, Hide for 1 hour, Quit)
- Removed: `toggle_panel`, `close_panel`.

Tray: Show/Hide pet, Settings, Quit. Global shortcut **Ctrl+Alt+P** toggles pet visibility. When the pet is shown this way, the backend emits `pet-open {view:"compose"}`.

## 6. Pet window UI (frontend)

Look: clean, compact, ChatGPT-like.
- Cards use `--surface` (white in light mode, #1f1f1f in dark), 12 px radius, 1 px hairline border, soft shadow (`0 8px 24px rgb(0 0 0 / .18)`), 13 px system UI font (`"Segoe UI Variable", system-ui`), 150–200 ms ease-out transitions.
- No emoji. Icons are inline SVG (Lucide-style strokes).

- **Bubble stack:** up to 3 thread cards; beyond that, a "+N more" pill that expands the stack.
  - Card contents: status indicator (running = spinning ring; needs_input = amber dot with pulse; ready = green check; blocked = red ×), project name (semibold), one-line label or excerpt (muted, ellipsis), relative time ("2m").
  - The newest card has a small tail pointing at the pet.
  - Hovering a card shows a × that calls `mark_viewed`.
  - Clicking an Ask card opens the thread view. Clicking a Watch card calls `mark_viewed` then `open_project`.
- **Control bar:** a pill under the pet with three icon buttons.
  - Pencil: composer. Bell: notifications toggle (filled when on). Chevron: collapse or expand bubbles.
  - Visible while hovering the pet or bar, while the composer or thread view is open, or while any thread is visible. Fades otherwise.
  - When collapsed, a count badge on the pet shows the number of visible threads.
- **Composer card:**
  - Project chip (dropdown: recent projects, then "Choose folder…" via the dialog plugin).
  - Mode chip (Read only / Edit files / Auto).
  - Auto-growing textarea (1–6 lines, "Ask Claude Code…"). Enter sends, Shift+Enter adds a newline, Esc closes.
  - Send arrow button.
  - The first send shows the credits notice inline in the card.
- **Thread view card:** about 340×400.
  - Header: project name, status, "New chat", close.
  - Scrolling messages, rendered as Markdown with code highlighting. Notes for blocked or stopped runs.
  - Inline follow-up composer, with a Stop button while running.
  - Calls `set_focused_thread` on open and close, and `mark_viewed` when opened or when a run finishes while open.
- **Setup bubble:** when `setup.needsSetup`, a single card "Finish setting up Perch" opens the settings window.
- **Pet sprite:** a div with background-image set to the atlas data URL, sized `1536*s × 1872*s`, with background-position chosen per frame and `image-rendering: pixelated`. Scale `s` is `config.petScale`. The sprite is the drag handle: after 4 px of movement it keeps pointer capture and moves the window itself via `drag_pet_by`, not the OS drag loop, during which the webview receives no events and the pet couldn't run. A click without movement toggles the composer. Right-click calls `show_pet_menu`.
- **Hit regions:** every interactive element carries `data-hit`. A single observer (ResizeObserver, MutationObserver and state changes) sends `set_hit_regions` throttled to 60 ms.

## 7. Settings window UI

Same design tokens as the pet window, in a normal window.
- **Onboarding**, 3 steps:
  1. Choose your pet (grid of pet cards with a live idle animation) and name it.
  2. Watch your sessions (install hooks, or skip).
  3. Claude Code check. Finish.
- **Settings sections:**
  - Pet: picker grid, name, size S/M/L.
  - Claude Code: checks, Check again, choose file, auto-detect.
  - Watching: install/remove hooks, move port.
  - Notifications & startup.
  - Cost: usage-credits line and link.
  - About: version, GitHub link, "Not affiliated with Anthropic", "Pet format compatible with Codex pets; drop pets into `~/.codex/pets` or Perch's pets folder" (with an Open folder button).

## 8. Out of scope

Voice input, creating pets from images, answering permission prompts from the pet, and signed installers.
