# Perch v1.0: design

Status: in progress · Builds on `2026-09-26-perch-v0.2-design.md`. That doc stays the base contract; this one lists v1.0 changes and decisions. Gates and evidence are in `docs/release/v1.0.0.md`.

## 1. Goals

A v1.0.0 that a stranger can download, install, trust, use daily, update and uninstall cleanly:

- Verified on Windows 11.
- Honestly labelled beta on macOS and Linux.
- Free to run: no paid services, no API keys.

## 2. Verified facts (Claude Code 2.1.282, 2026-09-26)

Measured live with a stand-in hook server and tiny `claude -p` runs.

**PermissionRequest hook**
- Fires in `-p` runs with `--permission-prompts none`.
- Payload keys: `session_id`, `transcript_path`, `cwd`, `scratchpad_dir`, `prompt_id`, `permission_mode`, `hook_event_name`, `tool_name`, `tool_input`, `permission_suggestions`. There is no `tool_use_id`.
- Bash and PowerShell inputs carry `command` and `description`.
- Example suggestions: `{"type":"setMode","mode":"acceptEdits","destination":"session"}` and `{"type":"addDirectories","directories":[…],"destination":"session"}`.

**Answers to a PermissionRequest**
- `{"hookSpecificOutput":{"hookEventName":"PermissionRequest","decision":{"behavior":"allow"}}}` runs the tool.
- `"deny"` with a `message` blocks it. The stream shows `system/permission_denied` with `decision_reason_type:"hook"` and the message; Claude may retry another way.
- A 5 s hold before allowing works; the run simply waits.
- A hook that times out gives no decision, so the tool is denied in `-p` ("no approval surface").

**Other flags**
- `--setting-sources user` skips the project's `.claude/settings.json`: its hooks, and presumably its `env`. User-level hooks still run.

**Hooks when Perch isn't running** (connection refused)

| Hook | What the user sees |
|---|---|
| `Stop` over HTTP | `system/notification` "Stop hook error occurred · ctrl+o to see" after every turn. `"async": true` doesn't suppress it. |
| `SessionEnd` over HTTP | "SessionEnd hook [...] failed: connect ECONNREFUSED" on stderr when a session exits. |
| `SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `PermissionRequest` over HTTP | Nothing, and no added delay. |
| Async command hooks that exit 0 | Nothing. |

**Not measured:** whether the interactive dialog (terminal or VS Code) waits for a pending PermissionRequest hook. Driving an interactive TUI needs keystroke injection while the owner is using the machine, which is unsafe. Design assumes it **does wait**; see D3.

## 3. Hook entries (v1)

All entries point at Perch's localhost server with the existing 64-hex token.

| Event | Handler | Why |
|---|---|---|
| SessionStart, UserPromptSubmit, PreToolUse, PostToolUse, PostToolUseFailure, Notification, PermissionDenied | `http`, timeout 2 | Silent when Perch is down, and no spawn cost on frequent events |
| PermissionRequest | `http`, timeout 75 | Sync decision. Perch always answers before its hold ends (≤ 60 s). |
| Stop, StopFailure, SessionEnd | `command`, `async: true`: `"<perch exe>" --hook-relay <port> <token>` | HTTP versions show error noise when Perch is quit (§2). The relay posts stdin to Perch and always exits 0 within ~1 s. |

Each entry is its own group, exactly:

```json
{ "hooks": [ { "type": "http", "url": "http://127.0.0.1:<port>/hook/<token>", "timeout": 2 } ] }
{ "hooks": [ { "type": "http", "url": "http://127.0.0.1:<port>/hook/<token>", "timeout": 75 } ] }
{ "hooks": [ { "type": "command", "command": "\"<perch exe>\" --hook-relay <port> <token>", "async": true } ] }
```

- **Identification.** An entry is Perch's if its URL matches `http://127.0.0.1:<port>/hook/<64 hex>`, or its command contains `--hook-relay <port> <64 hex>`. Uninstall removes exactly those hook objects (and only the groups, event keys and `hooks` object that become empty because of it); everything else keeps its value.
- **Status.** `current` when Perch's hook objects mean the same as the 11 above; `outdated` when any Perch entry exists but the set differs; `not installed` otherwise. Only `current` counts as installed.
  - "Mean the same" compares each entry's event, `type`, `url` or `command`, `timeout` as a number (so `2` and `2.0` match) and `async` (missing means false).
  - Key order and extra fields don't count.
- **Migration.** On launch, if hooks are `outdated` (for example, v0.2's 7 HTTP entries, another port, or a moved executable), reinstall once with the usual backup. Perch never rewrites the file on every start or quit. It doesn't migrate at all while running from a temporary location (see below).
- **Relay path.** The relay uses `std::env::current_exe()`, so a dev build installs dev paths. QA always reinstalls from the installed build. In a Linux AppImage it uses `$APPIMAGE` (the mount path changes every launch). The path is only double-quoted, never escaped. Stop, StopFailure and SessionEnd fall back to `http`, timeout 2 (like the other HTTP entries) when the path can't be used:
  - **Temporary location:** the path contains `/AppTranslocation/` (macOS App Translocation) or starts with `/Volumes/` (run from a mounted disk image). It would be gone after this run. Existing hooks aren't migrated, a fresh install uses the HTTP fallback, a warning is logged, and `setup.setupHint` says to move Perch to Applications.
  - **Shell characters:** the path contains `$`, `` ` ``, `"`, `%`, `!` or a control character, or a `\` outside Windows. bash and cmd expand these differently inside double quotes. A warning is logged.
  - Once a usable path exists, the HTTP fallback counts as `outdated` and is migrated to the relay.
- **Relay behavior.** Reads stdin (at most 4 MB, the hook server's cap; larger bodies are dropped), POSTs it to `http://127.0.0.1:<port>/hook/<token>` with 1 s connect, write and read timeouts, prints nothing, and always exits 0. A watchdog ends it after 5 s even if stdin never closes. Malformed arguments exit 0 without sending.
- **settings.json writes.** Written to `settings.json.perch-tmp` and renamed over the file. If the file changed between Perch's read and its write, Perch starts over from the new content, up to 3 times, then gives up with a message. Invalid JSON or invalid UTF-8 is never rewritten. A backup `settings.json.perch-backup-<epoch s>[-n]` is saved before each change. Old backups are pruned to the newest 5 only after the new file is in place. If the rename fails, the temp file and the new backup are removed and nothing is pruned. A symlinked settings.json stays a symlink (its target is replaced), and on Unix the new file and backup keep the original's permissions.

**Hook server.** `POST /hook/<token>` on 127.0.0.1. The token is compared in constant time. Every response is `Content-Type: application/json`: 404 for a wrong path or method, 503 when too many are in flight, otherwise 200.
- **Workers.** Each request is read on its own worker thread, at most 32 at once (beyond that it answers 503 at once).
- **Events.** Every body except PermissionRequest is answered `{}` immediately. It is then applied on one processing thread, in arrival order (requests are numbered as they arrive and applied in that order). A request whose body stalls holds later events back for at most 2 s; if it arrives after that, its event is dropped. The backend's `on_event: FnMut(Value) + Send` runs there.
- **PermissionRequest.** Calls `on_permission: Fn(Value) -> String + Send + Sync` on its worker, and the return value is the response (empty or a panic means `{}`). It may block; a held request never delays other events. Until approvals land, it answers `{}` (no decision) at once.
- **Size.** Bodies up to 4 MB are read. A larger body is drained, answered 200 `{}` and ignored (logged at debug). Size never causes an error answer, because Claude Code would show one as a hook error.
- **Late events.** After SessionEnd, the session's late events (a Stop relayed after its SessionEnd by a separate process, steps, needs-input) are ignored for 10 s. UserPromptSubmit or SessionStart (a resumed session) clears that at once.

## 4. Contract changes

**Config keys** (new, in `config.json`, all with defaults)

| Key | Default | Purpose |
|---|---|---|
| `autoUpdate` | `true` | Check for updates at launch and daily |
| `lastUpdateCheck` | `null` | Epoch ms of the last successful check (update found or none newer), automatic or manual |
| `watchApprovals` | `false` | Answer permission requests of watched sessions from the pet |
| `approvalHoldSecs` | `15` | How long to hold a watched request for a pet answer (UI offers 0/10/15/30/60) |
| `approvalsIntroSeen` | `false` | One-time intro card |
| `diagnosticsLevel` | `"info"` | Log level: `off`, `error`, `warn`, `info`, `debug` or `trace`, any case (anything else reads as `info`). Read at startup. |

**projects.json.** `ProjectEntry.trusted: bool`: trusted in Perch (D6). Default `false`; files without it load as `false`.

**Snapshot additions**
- `setup.setupHint: string | null`: advice that doesn't block setup and doesn't set `needsSetup`. Today the only hint is "Move Perch to Applications and open it from there…", shown while Perch runs from a temporary location.
- `update: UpdateStatus`, where `{ state: "idle"|"checking"|"available"|"downloading"|"ready"|"error"|"disabled", version?, notes?, progress?, error? }`.
  - Unset fields are left out of the JSON.
  - `progress` is a whole percent (0–100) while downloading; absent when the server sends no size.
  - `error` is set for `error` (a short message, see D13) and for `disabled`, which means a development build without `PERCH_UPDATE_ENDPOINT` ("Updates are off in development builds.").
- `approvals: PendingApproval[]`, where `{ id, sessionId, project, projectName, source: "watch"|"ask", toolName, summary, description|null, canAlwaysAllow, expiresAt|null }`.
  - `summary` is the exact command, file path or URL.
  - `expiresAt` is `null` for Ask requests, which are held until answered or the hook deadline.
- `usage: UsageInfo | null`, where `{ status, resetsAt?, utilization?, kind?, seenAt }` (D18). The latest plan usage an Ask run reported; `null` until the first `rate_limit_event` since launch (memory only, never saved).
  - `status` is Claude Code's string (`allowed`, `allowed_warning`, `rejected`, or anything newer).
  - `resetsAt` and `seenAt` are epoch ms; `utilization` is 0–1; `kind` is `rateLimitType` (`five_hour`, `seven_day`, `seven_day_opus`, `seven_day_sonnet`, …). Unset fields are left out of the JSON.

**Commands (new)**

| Command | What it does |
|---|---|
| `check_for_update` | Manual check. Returns UpdateStatus once the check is done; a found update keeps downloading in the background. While a check or download is running, or updates are disabled, it just returns the current status. While `ready` it still checks, quietly (see D13). |
| `install_update` | Refused while an Ask run is active ("Finish or stop the running ask first.") or before an update is ready; otherwise installs and relaunches. `ask` refuses once an install has begun. |
| `set_auto_update {enabled}` | Returns Snapshot |
| `answer_approval {id, decision: "allow"\|"deny"\|"always"}` | |
| `set_watch_approvals {enabled}` | |
| `set_approval_hold {secs}` | |
| `mark_approvals_intro_seen` | |
| `trust_project {project}` | Sets `trusted: true` on a known project (else "Unknown project.") and saves `projects.json` atomically (temp file, then rename); a change that can't be saved is undone and returned as an error. Returns Snapshot. |
| `untrust_project {project}` | The reverse: `trusted: false`. Returns Snapshot. |
| `get_diagnostics` | Returns a string: app version, OS and arch, Claude Code version, path and how it was found, login check, hook status, hook server port or error, settings and log paths, and the last 200 log lines. The hook token (and any 64-hex run) reads `<token>` and the home folder reads `~`. |
| `open_log_folder` | Creates the log folder if needed and opens it in the file manager |

**Events.** No new event names; everything rides on `snapshot`, except the untrusted-folder notice (D6), which rides on `pet-event` like the rest of an Ask's chat, and notification clicks (D17), which ride on `pet-open`:
- `pet-open` `{ view: "thread", sessionId }` gains optional `project` and `source` (`"watch"|"ask"`). A notification click sends both. The pet opens the thread exactly as a click on its card does, using the listed thread when it's still on the cards and one rebuilt from `project`/`source` when it isn't. Without them (the older form), the project comes from the listed thread or the project whose `askSessionId` matches, and the thread opens as an Ask.
- New `Kind` `untrusted`, Ask only: `label` is the headline, `text` the "Skipped: …" sentence, `sessionId` the conversation's id (empty for a new chat, whose id isn't known yet).
- Sent once per run, after the process starts and before any of its output. It never changes a thread or the snapshot.
- The frontend adds it to the mini chat as `ChatTurn { role: "untrusted", text: <headline>, detail: <skipped> }`. It isn't in the transcript, so it's gone once the conversation reloads.

**CLI.** `perch --uninstall-hooks` (headless: remove hooks from `$CLAUDE_CONFIG_DIR` or `~/.claude` `settings.json`, then the start-at-login entry: the HKCU `Run` and `StartupApproved\Run` values named `Perch` via a hidden `reg delete` on Windows, `~/Library/LaunchAgents/Perch.plist` on macOS, `~/.config/autostart/Perch.desktop` on Linux; exits 0, or 1 if settings.json couldn't be updated) and `perch --hook-relay <port> <token>` (headless relay, see §3; always exits 0). Both are handled at the very top of `run()`, before any Tauri or single-instance setup, so a running Perch never sees them. `--hook-relay` wins if both appear.

## 5. UI states (new)

**Cards**
- **Update ready.** "Perch <version> is ready. Restart to install." with Restart and Later. Only shown when no Ask run is active. Later hides it until the next launch or a newer version. Sits above the thread cards.
- **Approval.** Project, tool, the exact command/file/URL in monospace, Claude's description, and buttons **Deny** / **Allow**, plus **Always allow** when Claude Code sent a suggestion.
  - Nothing is focused by default, and Enter is never bound to Allow.
  - A watched request shows a countdown bar for the hold. One card per request.
- **Approvals intro** (once, after upgrading). Explains the feature and offers "Turn on".

**Mini chat.** Inline approval rows for Ask runs. Stop and New chat cancel pending requests. The untrusted-folder notice is a distinct system row (not Claude's text), once per run: the headline, what was skipped, and **Trust this folder in {pet}**. Once the folder is trusted, every such row in the chat reads "Trusted in {pet}. The next Ask uses this folder's settings." with a **Stop trusting** link.

**Mini chat footer.** When `usage.status` is `allowed_warning` or `rejected`, a muted line under the reply box: "Near your 5-hour limit (82%), resets 3:10 PM · as of 2:05 PM" or "5-hour limit reached, resets 3:10 PM · as of 2:05 PM". Nothing for `allowed` or an unknown status.

**Settings**
- Cost: under the existing text, "Plan usage: 42% of your 5-hour limit, resets 3:10 PM (as of 2:05 PM, from your last Ask)", or "Plan usage shows here after your next Ask." while `usage` is `null`. Without `utilization` it says "within", "close to" or "used up" by status ("no details reported" for an unknown one); a missing reset time is left out, a passed one reads "reset at". Times are local: a time today, a weekday within about a week, otherwise a date.
- Approvals: watch-approvals toggle and hold selector.
- Trusted folders (only while there is one): each folder trusted in Perch, its path, and **Stop trusting**.
- About: current version; "Check for updates automatically" toggle; "Check for updates" with an inline status (checking, up to date, available, downloading x%, ready with "Restart to update", couldn't check); Copy diagnostics (with a "Copied" confirmation); Open log folder; third-party licenses (`THIRD_PARTY_NOTICES.md` on GitHub).

## 6. Decisions

| # | Decision | Why |
|---|---|---|
| D1 | Hook relay (async command) only for Stop, StopFailure and SessionEnd | These were the only noisy events measured; HTTP stays on frequent events, so there's no per-tool-call process spawn |
| D2 | PermissionRequest over HTTP with timeout 75; Perch caps holds at 60 s | Silent when Perch is down; Perch always answers before Claude Code gives up |
| D3 | Watch approvals: when a Claude Code host (VS Code, Cursor, Windsurf, Windows Terminal, conhost, cmd, PowerShell, pwsh, `claude`) is the foreground window, answer `{}` at once. Otherwise hold up to `approvalHoldSecs` (15). Off by default. | The dialog-wait behavior is unmeasured, so assume it waits. Someone at the keyboard never waits; the feature is opt-in. |
| D4 | Ask approvals on by default, held until answered, capped at 60 s, then `{}` (tool denied, noted in the chat) | Without it, `--permission-prompts none` just denies |
| D5 | "Needs input" comes from PermissionRequest immediately. It clears on PostToolUse, PostToolUseFailure, PermissionDenied, UserPromptSubmit, Stop or SessionEnd for that session. | Instant signal; also cleared when answered natively |
| D6 | **Untrusted folders for Ask** (`trust.rs`, decided in the `ask` command at every Ask). **(1) Trusted by Claude Code:** `projects[K].hasTrustDialogAccepted == true` in `$CLAUDE_CONFIG_DIR/.claude.json`, else `~/.claude.json`, for a key K with the folder at or under K. Inside a git repository (nearest `.git` folder or file, root R), K must also be at or under R: the repository root or a folder inside it. A trusted home or projects folder doesn't cover a repository cloned under it, and an outer repository's key doesn't cover a nested one (a submodule or worktree), matching Claude Code, which shows the trust dialog for a nested repository. Outside any repository, any parent counts. The file is read fresh each Ask, read-only, at most 32 MB. Keys and paths match whole component by component (`C:/p/proj` doesn't trust `C:/p/proj2`) and ignore a trailing separator; on Windows also case and `\` vs `/`, with a verbatim prefix removed (`\\?\C:\x` is `C:/x`, `\\?\UNC\server\share` is `//server/share`). A missing, unreadable, oversized or malformed file means "not trusted", never an error. **(2) Trusted in Perch:** `ProjectEntry.trusted`, per project folder (exact path). **(3) What it would run:** the folder and, inside a git repository (nearest `.git` folder or file), the repository root: hook event names, `env` key names (never values) and helper keys (`apiKeyHelper`, `awsAuthRefresh`, `awsCredentialExport`, `gcpAuthRefresh`, `otelHeadersHelper`, any other `*Helper`) in `.claude/settings.json` and `.claude/settings.local.json`; server names in `.mcp.json`'s `mcpServers`; the number of folders in `.claude/skills/`. At most 1 MB per file; a file that isn't a regular file, is bigger, or doesn't parse to an object lists as "project settings (couldn't be read)". The user's own settings folder (`$CLAUDE_CONFIG_DIR` or `~/.claude`, e.g. when asking in the home folder) never counts as a project's `.claude`. **(4) Decision:** trusted either way, or nothing found (no `.claude` folder and no `.mcp.json` in either place): normal flags, no notice. Otherwise `--setting-sources user` (appended through `AskRequest.extra_args`, after every other flag) and a notice (§4 Events): "This folder isn't trusted in Claude Code yet, so {pet} ran without its project settings. Skipped: hooks (PreToolUse, Stop) · environment variables (ANTHROPIC_BASE_URL, FOO) · MCP servers (db, github) · apiKeyHelper · 2 project skills." Names are sorted, at most 6 per kind then "+N more", without control characters and cut to 40 characters; with nothing specific it says "project settings". **(5) Trust and undo:** the notice's **Trust this folder in {pet}** calls `trust_project`; the next Ask uses the folder's settings. Undo with **Stop trusting** on the same row or in Settings → Trusted folders (`untrust_project`). The log records counts only. | A `-p` run never shows the trust dialog and treats its folder as trusted, so it would run the repository's hooks, `env`, helpers, skills and MCP servers. Verified that the flag skips project hooks; per the docs it reads neither project settings files nor `.mcp.json`. Read-only on Claude Code's own state. |
| D7 | Updater endpoint is `…/releases/latest/download/latest.json`; the env var `PERCH_UPDATE_ENDPOINT` overrides it for RC testing | `/latest` ignores pre-releases |
| D8 | Logging via `tauri-plugin-log` to `<app log dir>/perch.log`, rotating at 1 MB with at most 5 files, plus stdout in debug builds. A panic hook logs the message, location and backtrace, then runs the default hook. Locks go through a poison-tolerant helper. The token is never logged. | Diagnosable in the field without panicking on a poisoned lock |
| D9 | Edges (M9): the sprite, not the window, is clamped into the work area, so it can sit flush against every edge and corner; the window is free to extend off-screen around it. `overlay.rs`'s `place_sprite` computes `{cardsBelow, shiftX}` from the sprite's clamped screen rect and the work area, with hysteresis (below 320 logical px of room above, cards flip below; above 380, they flip back) so it doesn't flicker at the threshold. It moves the window (keeping the sprite at the same screen spot) whenever the flip changes, and emits `pet-placement` to the pet window. The frontend applies `cardsBelow` as a `data-cards-below` attribute on `.overlay`, which CSS turns into a flipped `.dock` flex `order` (and flipped card animation origins and tail direction), and `shiftX` as a `transform: translateX()` on `.stage` — generic to whatever renders there, so it also covers M2's approval cards. `place_sprite` also reports `stageRoom`, how much of the stage's natural height is actually on screen (capped at 0), applied as a `--stage-room` custom property / `max-height` on `.stage` so content shrinks or scrolls instead of being cut off when the window's top or bottom edge is off-screen. A saved anchor whose monitor has vanished (or nothing saved at all) falls back to the default position via a pure `resolve_sprite_anchor`, restoring gate G3.5's off-screen recovery. A saved position now means the sprite's top-left, not the window's; a v0.2 (window-anchored) value is migrated once, on first load, then re-saved so it isn't migrated again (gate G2.2). | Lets the pet sit flush in corners (M9) |
| D10 | CSP locked down. Markdown images render as alt text; links open in the system browser. The start-dragging capability is dropped. Pet sprites must be a regular file (not a symlink) that resolves inside the pet folder, ≤ 20 MiB, and exactly 1536×1872 by the PNG IHDR or WebP VP8/VP8L/VP8X header (this replaces v0.2's "dimensions are not checked"). | No remote content in the webview |
| D11 | Uninstall: `src-tauri/windows/installer.nsh` (`bundle.windows.nsis.installerHooks`) defines `NSIS_HOOK_PREUNINSTALL`, which runs `"$INSTDIR\perch.exe" --uninstall-hooks` with `ExecWait` unless `$UpdateMode = 1`. The updater runs the installer with `/UPDATE`; in that mode Tauri's installer doesn't run the uninstaller at all, and forwards `/UPDATE` if it ever does. Choosing "uninstall before installing" when running a newer installer by hand is a real uninstall, so hooks are removed and the new build asks to reinstall them. | Clean removal; updates keep hooks |
| D12 | CI runs `vitest run` without `--passWithNoTests` | A worker startup failure once reported "no tests" and passed |
| D13 | Updates run in Rust (tauri-plugin-updater; the webview gets no updater permissions). With `autoUpdate` on: a check 30 s after launch, then whenever `lastUpdateCheck` is 24 h old (polled every 10 min). `lastUpdateCheck` is stamped only on success; after a failed check or download the next attempt comes 1 h later, doubling per consecutive failure up to 24 h. A found update downloads in the background and its minisign signature is verified; the bundle is written to `<app cache>/updates/` (not kept in memory) and waits as `ready`. Checks keep running while `ready`: the ready update stays offered, and only a newer version, once downloaded and verified, replaces it (the older file is deleted, and the card comes back even after Later). Bundles left by earlier runs are deleted at startup. Background failures (offline, 404, no `latest.json`) are logged and go back to `idle`; a manual check shows "Couldn't check for updates." or "Couldn't download the update."; a bad signature is always shown (while `ready`, failures only log and the ready update stays). Windows installs with NSIS `/P /UPDATE /R`: Perch exits and the installer relaunches it. macOS/Linux replace the app, then Perch restarts itself (`AppHandle::request_restart`, so no tauri-plugin-process). `PERCH_UPDATE_ENDPOINT` must be `https` in release builds. | Quiet by default; never restarts mid-Ask; `/releases/latest` has no `latest.json` until the first v1 release |
| D14 (M9) | `shell::open_project` (v0.2 §5) tries, in order: `code`/`code.cmd` on PATH; known per-OS install locations (Windows: `%LOCALAPPDATA%\Programs`, `%ProgramFiles%`, `%ProgramFiles(x86)%`; macOS: `/Applications` and `~/Applications`; Linux: the usual distro/Snap/Flatpak paths); the `vscode://file/<path>/` URL through the opener plugin, only when the scheme is safe (Windows: `HKCU\Software\Classes\vscode` or `HKCR\vscode` exists, checked with `reg query`; macOS/Linux: VS Code's app or a `code-url-handler.desktop` was actually found); then the file manager. The URL builder forward-slashes the path and percent-encodes everything outside RFC 3986 unreserved characters plus `/` and `:` (so `?`, `#`, `%`, spaces and non-ASCII are all escaped; a literal `?` would otherwise start a query string and truncate the path). | Many people have VS Code without `code` on PATH; the URL step never shows Windows' "how do you want to open this?" |
| D15 (M9) | Claude Code's binary is re-located (design gap G3.5) whenever the remembered path fails a fresh `locate` check (missing, or `--version` fails): before every Ask spawn (`state::ensure_claude_located`), on a plain setup recheck, and once more if the spawn itself fails with "not found" (an update can move the path between the check and the spawn). `locator::relocate`/`is_stale` are pure; a stale user-chosen path is skipped like any missing candidate, so it falls back to auto-detect on its own. The money guard's auth check always runs against whichever binary is about to be used. | The VS Code extension's bundled binary moves to a new versioned folder on every update |
| D16 (M9) | Recheck (`state::compute_recheck`) always re-runs `locate` and `claude auth status` fresh; nothing in Perch caches or reuses a previous verdict. The plan label reads "Logged in with Claude \<Plan\> (as reported by Claude Code)", since `subscriptionType` can be stale in Claude Code's own account cache regardless of how often Perch asks. | Honest about what Perch can and can't verify |

| D17 | **Notification clicks (Windows).** `notify.rs`: `notice_for` maps a thread entering ready, needs-input or blocked to `{title, body, target}` (title "{pet} · {project}", body as in v0.2; `target` is the thread's session id, project and source). The notifications toggle and the focused-thread rule (no toast for the thread open in the mini chat) are unchanged. On Windows the toast is shown with `tauri-winrt-notification` directly (the same crate and version the plugin reaches through notify-rust), built exactly as the plugin built it: title, an empty first line, the body, silent, short, no buttons. Its app id is chosen as the plugin chooses it: the bundle identifier `io.github.perchpet.perch` (registered by the NSIS Start-menu shortcut) unless the executable is in Cargo's `target\debug` or `target\release`, where it's PowerShell's id so the toast still shows. The toast's `Activated` callback runs in Perch's process; on the main thread it shows the pet, focuses it and emits `pet-open {view: "thread", sessionId, project, source}` (§4 Events), which opens an Ask thread's mini chat or runs a Watch card's action (mark viewed, open the project). ## 7. Deferred (with reasons)

- **Replying into live VS Code or terminal sessions.** Channels are a research preview, and concurrent use is risky.
- **Paid signing or notarization.** Money rule. Free OSS code signing (e.g. SignPath Foundation) is an optional step for the owner.
- **Measuring the interactive dialog wait.** Needs keystroke injection while the owner uses the machine; D3 covers the risk.
- **Not in v1.0:** voice input, hatching pets from images, per-monitor pets, i18n, Claude Code plugin packaging.
