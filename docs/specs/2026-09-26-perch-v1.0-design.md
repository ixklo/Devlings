# Perch v1.0: design

Status: in progress · Builds on `2026-09-26-perch-v0.2-design.md`. That doc stays the base contract; this one lists v1.0 changes and decisions. Gates and evidence are in `docs/release/v1.0.0.md`.

## 1. Goals

A v1.0.0 that a stranger can download, install, trust, use daily, update and uninstall cleanly:

- Verified on Windows 11.
- Honestly labelled beta on macOS and Linux.
- Free to run: no paid services, no API keys.

## 2. Verified facts (Claude Code 2.1.282, 2026-09-26)

Measured live with a stand-in hook server and tiny `claude -p` runs.

**PermissionRequest hook**
- Fires in `-p` runs with `--permission-prompts none`.
- Payload keys: `session_id`, `transcript_path`, `cwd`, `scratchpad_dir`, `prompt_id`, `permission_mode`, `hook_event_name`, `tool_name`, `tool_input`, `permission_suggestions`. There is no `tool_use_id`.
- Bash and PowerShell inputs carry `command` and `description`.
- Example suggestions: `{"type":"setMode","mode":"acceptEdits","destination":"session"}` and `{"type":"addDirectories","directories":[…],"destination":"session"}`.

**Answers to a PermissionRequest**
- `{"hookSpecificOutput":{"hookEventName":"PermissionRequest","decision":{"behavior":"allow"}}}` runs the tool.
- `"deny"` with a `message` blocks it. The stream shows `system/permission_denied` with `decision_reason_type:"hook"` and the message; Claude may retry another way.
- A 5 s hold before allowing works; the run simply waits.
- A hook that times out gives no decision, so the tool is denied in `-p` ("no approval surface").

**Other flags**
- `--setting-sources user` skips the project's `.claude/settings.json`: its hooks, and presumably its `env`. User-level hooks still run.

**Hooks when Perch isn't running** (connection refused)

| Hook | What the user sees |
|---|---|
| `Stop` over HTTP | `system/notification` "Stop hook error occurred · ctrl+o to see" after every turn. `"async": true` doesn't suppress it. |
| `SessionEnd` over HTTP | "SessionEnd hook [...] failed: connect ECONNREFUSED" on stderr when a session exits. |
| `SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `PermissionRequest` over HTTP | Nothing, and no added delay. |
| Async command hooks that exit 0 | Nothing. |

**Not measured:** whether the interactive dialog (terminal or VS Code) waits for a pending PermissionRequest hook. Driving an interactive TUI needs keystroke injection while the owner is using the machine, which is unsafe. Design assumes it **does wait**; see D3.

## 3. Hook entries (v1)

All entries point at Perch's localhost server with the existing 64-hex token.

| Event | Handler | Why |
|---|---|---|
| SessionStart, UserPromptSubmit, PreToolUse, PostToolUse, PostToolUseFailure, Notification, PermissionDenied | `http`, timeout 2 | Silent when Perch is down, and no spawn cost on frequent events |
| PermissionRequest | `http`, timeout 75 | Sync decision. Perch always answers before its hold ends (≤ 60 s). |
| Stop, StopFailure, SessionEnd | `command`, `async: true`: `"<perch exe>" --hook-relay <port> <token>` | HTTP versions show error noise when Perch is quit (§2). The relay posts stdin to Perch and always exits 0 within ~1 s. |

- **Identification.** An entry is Perch's if its URL matches `http://127.0.0.1:<port>/hook/<64 hex>`, or its command contains `--hook-relay <port> <64 hex>`.
- **Migration.** On launch, if hooks are installed but the set or shape differs (for example, v0.2's 7 HTTP entries), reinstall once with the usual backup. Perch never rewrites the file on every start or quit.
- **Relay path.** The relay uses `std::env::current_exe()`, so a dev build installs dev paths. QA always reinstalls from the installed build.

## 4. Contract changes

**Config keys** (new, in `config.json`, all with defaults)

| Key | Default | Purpose |
|---|---|---|
| `autoUpdate` | `true` | Check for updates at launch and daily |
| `lastUpdateCheck` | `null` | Epoch ms when the last check (automatic or manual) started |
| `watchApprovals` | `false` | Answer permission requests of watched sessions from the pet |
| `approvalHoldSecs` | `15` | How long to hold a watched request for a pet answer (UI offers 0/10/15/30/60) |
| `approvalsIntroSeen` | `false` | One-time intro card |
| `diagnosticsLevel` | `"info"` | Log level |

**projects.json.** `ProjectEntry.trusted: bool` (Perch-level trust for untrusted folders, M4).

**Snapshot additions**
- `update: UpdateStatus`, where `{ state: "idle"|"checking"|"available"|"downloading"|"ready"|"error"|"disabled", version?, notes?, progress?, error? }`.
  - Unset fields are left out of the JSON.
  - `progress` is a whole percent (0–100) while downloading; absent when the server sends no size.
  - `error` is set for `error` (a short message, see D13) and for `disabled`, which means a development build without `PERCH_UPDATE_ENDPOINT` ("Updates are off in development builds.").
- `approvals: PendingApproval[]`, where `{ id, sessionId, project, projectName, source: "watch"|"ask", toolName, summary, description|null, canAlwaysAllow, expiresAt|null }`.
  - `summary` is the exact command, file path or URL.
  - `expiresAt` is `null` for Ask requests, which are held until answered or the hook deadline.

**Commands (new)**

| Command | What it does |
|---|---|
| `check_for_update` | Manual check. Returns UpdateStatus once the check is done; a found update keeps downloading in the background. While checking, downloading, ready or disabled it just returns the current status. |
| `install_update` | Refused while an Ask run is active ("Finish or stop the running ask first.") or before an update is ready; otherwise installs and relaunches. `ask` refuses once an install has begun. |
| `set_auto_update {enabled}` | Returns Snapshot |
| `answer_approval {id, decision: "allow"\|"deny"\|"always"}` | |
| `set_watch_approvals {enabled}` | |
| `set_approval_hold {secs}` | |
| `mark_approvals_intro_seen` | |
| `trust_project {project}` | |
| `get_diagnostics` | Returns redacted text |
| `open_log_folder` | |

**Events.** No new event names; everything rides on `snapshot`.

**CLI.** `perch --uninstall-hooks` (headless: remove hooks and the start-at-login entry, exit) and `perch --hook-relay <port> <token>` (headless relay). Both are handled before any Tauri or single-instance setup.

## 5. UI states (new)

**Cards**
- **Update ready.** "Perch <version> is ready. Restart to install." with Restart and Later. Only shown when no Ask run is active. Later hides it until the next launch or a newer version. Sits above the thread cards.
- **Approval.** Project, tool, the exact command/file/URL in monospace, Claude's description, and buttons **Deny** / **Allow**, plus **Always allow** when Claude Code sent a suggestion.
  - Nothing is focused by default, and Enter is never bound to Allow.
  - A watched request shows a countdown bar for the hold. One card per request.
- **Approvals intro** (once, after upgrading). Explains the feature and offers "Turn on".

**Mini chat.** Inline approval rows for Ask runs. Stop and New chat cancel pending requests. An untrusted-folder notice offers "Trust this folder in Perch".

**Settings**
- Approvals: watch-approvals toggle and hold selector.
- About: current version; "Check for updates automatically" toggle; "Check for updates" with an inline status (checking, up to date, available, downloading x%, ready with "Restart to update", couldn't check); Copy diagnostics (with a "Copied" confirmation); Open log folder; third-party licenses (`THIRD_PARTY_NOTICES.md` on GitHub).

## 6. Decisions

| # | Decision | Why |
|---|---|---|
| D1 | Hook relay (async command) only for Stop, StopFailure and SessionEnd | These were the only noisy events measured; HTTP stays on frequent events, so there's no per-tool-call process spawn |
| D2 | PermissionRequest over HTTP with timeout 75; Perch caps holds at 60 s | Silent when Perch is down; Perch always answers before Claude Code gives up |
| D3 | Watch approvals: when a Claude Code host (VS Code, Cursor, Windsurf, Windows Terminal, conhost, cmd, PowerShell, pwsh, `claude`) is the foreground window, answer `{}` at once. Otherwise hold up to `approvalHoldSecs` (15). Off by default. | The dialog-wait behavior is unmeasured, so assume it waits. Someone at the keyboard never waits; the feature is opt-in. |
| D4 | Ask approvals on by default, held until answered, capped at 60 s, then `{}` (tool denied, noted in the chat) | Without it, `--permission-prompts none` just denies |
| D5 | "Needs input" comes from PermissionRequest immediately. It clears on PostToolUse, PostToolUseFailure, PermissionDenied, UserPromptSubmit, Stop or SessionEnd for that session. | Instant signal; also cleared when answered natively |
| D6 | Untrusted-folder Asks run with `--setting-sources user` plus a notice listing what was skipped (project hooks, `.mcp.json` servers, `env` key names). "Trust in Perch" is stored per project. Trust is read from `~/.claude.json` (the path and its parents); Perch never writes that file. | Verified the flag skips project hooks. Read-only on Claude Code's own state. |
| D7 | Updater endpoint is `…/releases/latest/download/latest.json`; the env var `PERCH_UPDATE_ENDPOINT` overrides it for RC testing | `/latest` ignores pre-releases |
| D8 | Logging via `tauri-plugin-log`, rotating to the app log dir (1 MB × keep 5), with a panic hook. Locks go through a poison-tolerant helper. | Diagnosable in the field without panicking on a poisoned lock |
| D9 | Edges: the sprite, not the window, is clamped into the work area. The backend reports free space and flips cards below the pet near the top edge; cards shift sideways near the side edges. | Lets the pet sit flush in corners (M9) |
| D10 | CSP locked down. Markdown images render as alt text; links open in the system browser. The start-dragging capability is dropped. | No remote content in the webview |
| D11 | Uninstall: an NSIS pre-uninstall hook runs `perch.exe --uninstall-hooks`, skipped when updating | Clean removal; updates keep hooks |
| D12 | CI runs `vitest run` without `--passWithNoTests` | A worker startup failure once reported "no tests" and passed |
| D13 | Updates run in Rust (tauri-plugin-updater; the webview gets no updater permissions). With `autoUpdate` on: a check 30 s after launch, then whenever `lastUpdateCheck` is 24 h old (polled every 10 min). A found update downloads in the background and its minisign signature is verified, then waits as `ready`. Background failures (offline, 404, no `latest.json`) are logged and go back to `idle`; a manual check shows "Couldn't check for updates." or "Couldn't download the update."; a bad signature is always shown. Windows installs with NSIS `/P /UPDATE /R`: Perch exits and the installer relaunches it. macOS/Linux replace the app, then Perch restarts itself (`AppHandle::request_restart`, so no tauri-plugin-process). `PERCH_UPDATE_ENDPOINT` must be `https` in release builds. | Quiet by default; never restarts mid-Ask; `/releases/latest` has no `latest.json` until the first v1 release |

## 7. Deferred (with reasons)

- **Replying into live VS Code or terminal sessions.** Channels are a research preview, and concurrent use is risky.
- **Paid signing or notarization.** Money rule. Free OSS code signing (e.g. SignPath Foundation) is an optional step for the owner.
- **Measuring the interactive dialog wait.** Needs keystroke injection while the owner uses the machine; D3 covers the risk.
- **Not in v1.0:** voice input, hatching pets from images, per-monitor pets, i18n, Claude Code plugin packaging.
